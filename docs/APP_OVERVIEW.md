# Sketch2Spec — คู่มือแอปและเอกสารส่งต่องาน

อัปเดต: 21 กันยายน 2026

เอกสารนี้สรุปฟังก์ชันที่มีในโค้ดปัจจุบัน วิธีใช้งาน และจุดที่ผู้พัฒนาคนถัดไปควรรู้ รายละเอียดการแบ่งห้องอ่านเพิ่มได้ที่ [ห้อง พื้น และวัสดุ](rooms-and-materials.md)

## 1. แอปทำอะไร

Sketch2Spec เปลี่ยนภาพแปลนบ้านเป็นวัตถุที่แก้ไขได้ใน 2D และดูเป็นโมเดล 3D ผู้ใช้ตรวจแก้ผล AI เพิ่มหรือลบผนัง ประตู หน้าต่าง สร้างพื้น เลือกวัสดุ และประมาณราคาวัสดุเบื้องต้นได้

ขั้นตอนหลัก:

**อัปโหลดแปลน → เตรียมภาพ → Run AI Detection → ตรวจแก้ใน 2D → แบ่งห้อง/ดู 3D → เลือกวัสดุ → สำรองงานหรือส่งออก CSV**

สถานะ: แอปรันในเครื่อง โดยเปิด frontend และ backend แยกกัน ยังไม่ได้ deploy และยังไม่มีระบบบัญชีผู้ใช้หรือการซิงก์โปรเจกต์ข้ามเครื่อง

## 3. วิธีใช้สำหรับผู้ใช้

### เริ่มแปลนใหม่

1. เปิด `http://localhost:3000/upload` และตรวจว่า AI พร้อมใช้งาน
2. เลือกภาพหรือ PDF ถ้าเป็น PDF ให้เลือกหน้าที่ต้องการ จากนั้นครอป/หมุนและยืนยันภาพ
3. กด **Run AI Detection** แล้วตรวจผลใน **2D Review**
4. เพิ่มวัตถุที่ AI พลาด ลบวัตถุเกิน แก้ประเภท ตำแหน่ง และขนาดให้ตรงกับภาพจริง
5. กำหนดมาตราส่วนจากระยะที่ทราบจริง หากต้องการขนาดเป็นเมตรและประมาณราคา
6. เปิด **3D Editor** และตรวจว่าผนัง ช่องเปิด และห้องตรงกับแปลน
7. หลังแก้แนวผนังหรือเปิดงานเก่า กด **แบ่งพื้นตามห้อง** เพื่อสร้างขอบพื้นจากแนวล่าสุด การแบ่งใหม่ย้อนกลับได้ด้วย Undo

### การควบคุม 3D

- **หมุนดู 360°**: ลากเมาส์ซ้ายบนโมเดลเพื่อหมุน ลากบนพื้นห้องเพื่อเลื่อนกล้อง
- ลากเมาส์ขวาเพื่อเลื่อน และใช้ล้อเมาส์เพื่อซูม
- คลิกหนึ่งครั้งเพื่อเลือกวัตถุ หากวัตถุถูกบังให้ใช้รายการ **เลือกชิ้นงาน**
- กด **แก้ไขวัตถุ** เพื่อย้ายหรือปรับรูปทรง แยกจากการหมุนดู
- กด **คืนมุมกล้อง** เมื่อหลงมุมมอง
- `Command+Z` / `Command+Shift+Z` ใช้ Undo/Redo บน Mac และ `Esc` ยกเลิกการลากที่ยังไม่ยืนยัน

### ทาสีผนัง — เมนูปัจจุบัน

1. เปิด **วัสดุ & งบ → สีทาผนัง**
2. เลือก **ทั้งห้อง / ผนังเดียว / ทั้งแปลน**
3. สำหรับทั้งห้องหรือผนังเดียว เลือกชื่อห้อง หากเลือกผนังเดียวให้กดหมายเลขบนภาพห้องหรือปุ่มหมายเลขด้านล่าง ไม่ต้องเลือกซ้าย–ขวาซ้ำ
4. เลือกสีหรือวัสดุ แล้วตรวจข้อความสรุปกับขอบเขตสีม่วงบนโมเดล
5. กด **3. ทาสีผนัง** จึงจะใช้วัสดุจริง การเลือกตัวอย่างสีอย่างเดียวยังไม่เปลี่ยนโมเดล

**ทั้งห้อง** ทาเฉพาะด้านที่หันเข้าห้องนั้น ส่วน **ผนังเดียว** ทาเฉพาะช่วงผิวที่เลือกของห้อง ไม่ทาทั้งความยาวของผนังที่ผ่านหลายห้อง

**ทั้งแปลน** ทาผนังทุกชิ้นทั้งสองฝั่ง รวมด้านนอกบ้าน หากต้องการทั้งสองฝั่งของผนังชิ้นเดียว ใช้ **ตัวเลือกเพิ่มเติม**

สีที่เลือกคงอยู่เมื่อเปลี่ยนห้องหรือผนัง สามารถเริ่มจากพื้นห้องที่เลือกอยู่แล้วสลับไปทาผนังของห้องนั้นได้ หากยังไม่พบผนังที่ติดห้อง ให้แบ่งพื้นตามห้องใหม่หรือตรวจแนวที่ขาดก่อน

### วัสดุพื้นและงบประมาณ

เลือกพื้นหรือห้อง แล้วเปิดหมวด **กระเบื้องพื้น** เลือกขอบเขตและวัสดุ จากนั้นกดใช้วัสดุ ห้องรูปตัว L เปลี่ยนวัสดุทั้งห้องเป็นวัตถุเดียว

ต้องกำหนดมาตราส่วนก่อนคำนวณราคา ราคาที่มีเป็นค่าสาธิตใน `lib/materials.ts` ไม่ใช่ใบเสนอราคาหรือ BOQ สำหรับก่อสร้างจริง:

- พื้นใช้พื้นที่รูปทรงจริง ไม่ใช้กรอบสี่เหลี่ยมครอบห้องเว้า
- ผนังใช้ความยาว × ความสูง แยกตามฝั่งและช่วงที่ใช้วัสดุ ยังเป็นพื้นที่รวมก่อนหักช่องเปิด
- ประตูคิดเป็นชิ้น หน้าต่างใช้พื้นที่ประมาณ
- วัสดุเริ่มต้นที่เห็นใน 3D ยังไม่ถูกคิดราคา จนกว่าจะยืนยันใช้วัสดุ

### สำรองและส่งงาน

กด **สำรองโปรเจกต์** เพื่อดาวน์โหลด `.sketch2spec.json` และใช้ **เปิดโปรเจกต์** เพื่อแก้ต่อโดยไม่ต้องรัน AI ใหม่

การบันทึกอัตโนมัติอยู่ในเบราว์เซอร์เดิม ไม่ได้อยู่ใน GitHub และไม่ใช่การสำรองบนเซิร์ฟเวอร์ การส่งโค้ดให้เพื่อนไม่ได้ส่งแปลนที่กำลังเปิดอยู่ด้วย ต้องส่งไฟล์สำรองงานแยกต่างหาก

## 4. วิธีรันบนเครื่องใหม่

สภาพแวดล้อมที่ใช้ทดสอบงานล่าสุด: macOS, Node.js 26 และ Python 3.11 ส่วนคำสั่ง Windows อยู่ใน [README](../README.md)

จากโฟลเดอร์หลักของโปรเจกต์ ติดตั้งครั้งแรก:

```bash
npm ci
python3.11 -m venv backend/.venv
backend/.venv/bin/python -m pip install -r backend/requirements.txt
```

ต้องมี Python 3.11 และ Node.js/npm ติดตั้งอยู่ก่อน และต้องมีโมเดลเดิมที่ `backend/best.pt`

เปิด Terminal สองแท็บ จากโฟลเดอร์หลัก:

```bash
# แท็บที่ 1: Backend
backend/.venv/bin/python -m uvicorn main:app --app-dir backend --host 127.0.0.1 --port 8000
```

```bash
# แท็บที่ 2: Frontend
npm run dev -- --hostname 127.0.0.1
```

- เว็บ: `http://localhost:3000/upload`
- ตรวจ backend: `http://localhost:8000/health`
- เอกสาร API: `http://localhost:8000/docs`

เปิด Terminal ทั้งสองไว้ระหว่างใช้งาน ครั้งถัดไปใช้เพียงสองคำสั่งรัน ไม่ต้องติดตั้งใหม่ กด Control+C เพื่อหยุด

ค่าเริ่มต้น backend URL คือ `http://localhost:8000` หากเปลี่ยนพอร์ตให้ตั้ง `NEXT_PUBLIC_DETECTION_API_URL` ใน `.env.local` ดูตัวอย่างได้จาก [`.env.example`](../.env.example) แล้วเริ่ม frontend ใหม่

### ข้อมูลสำคัญ

- `Detection.box` ใช้พิกัดภาพแปลน ต้องรักษาความสอดคล้องกับขนาดภาพและมาตราส่วน
- `floorTiles` เก็บสี่เหลี่ยมย่อยแบบพิกัด 0–1 ภายในกรอบพื้น ใช้แทนห้องเว้าโดยไม่ปูทับส่วนที่ไม่ใช่ห้อง
- `roomName` เก็บชื่อห้อง
- `wallFinishes` เก็บ `side`, `start`, `end` และวัสดุ แต่ละช่วงอยู่ในสัดส่วน 0–1 ตามแนวยาวผนัง จึงแยกสีคนละฝั่ง/ห้องได้
- `materialApplied` ใช้ระบุการยืนยันวัสดุของวัตถุ ส่วนวัสดุรายผิวผนังเก็บใน `wallFinishes`
- เมื่อเพิ่มฟิลด์ใหม่ ต้องตรวจการ clone สำหรับ Undo/Redo การอ่านไฟล์สำรอง และการบันทึกกลับ ไม่ใช่แก้เฉพาะการแสดงภาพ

| `GET /health` | สถานะ backend และการมี dependency/ไฟล์โมเดล ไม่ใช่การยืนยันคุณภาพผลตรวจจับ |
| `POST /pdf/info` | อ่านจำนวนหน้า PDF |
| `POST /prepare` | เตรียมภาพ/แปลงหน้า PDF เป็น PNG ใช้ `page` เริ่มที่ 1 |
| `POST /detect/jobs` | เริ่มงานตรวจจับและคืน `job_id` |
| `GET /detect/jobs/{job_id}` | อ่านความคืบหน้า ผลลัพธ์ หรือข้อผิดพลาด |
| `DELETE /detect/jobs/{job_id}` | ลบรายการงานที่ติดตาม ไม่รับประกันหยุด inference ที่เริ่มแล้ว |
| `POST /detect` | ตรวจจับแบบรอผล สำหรับไคลเอนต์ที่ไม่ใช้ job polling |

ฝั่ง backend กำหนดไฟล์อัปโหลดสูงสุด 25 MB และขนาดด้านยาวของภาพที่เตรียมสูงสุด 2,000 พิกเซล ดู schema และพารามิเตอร์จริงที่ `/docs`

## 6. AI ทำอะไร และอะไรยังเป็นข้อจำกัด

โมเดลเดิมมี 3 คลาส: `door`, `wall`, `window` เท่านั้น **พื้นและห้องไม่ได้มาจากโมเดล segmentation** แต่เป็นการหาพื้นที่ปิดจากผลผนังและช่องเปิดหลังตรวจจับ

การซ่อมฝั่งแอปที่มีแล้ว:

- ใช้พิกัดขอบจริงเพื่อให้พื้นชิดผนัง แทนการปัดเข้าตาราง
- ลดช่องว่างจากกรอบสัญลักษณ์ประตู โดยใช้ความหนาผนังใกล้เคียงเมื่อหาแนวได้
- แยกวัสดุผนังตามฝั่งและช่วงห้อง
- กรองกรอบซ้ำแบบมีเกณฑ์ความซ้อน ไม่ใช่การทำให้โมเดลรู้จักวัตถุใหม่

ข้อจำกัดที่ยังต้องตรวจด้วยคน:

- ผนังขาด ตรวจผิดตำแหน่ง หรือประตู/หน้าต่างผิดประเภท อาจทำให้แบ่งห้องผิด
- พื้นที่เปิดเชื่อมกันที่ไม่มีขอบแบ่งอาจถูกนับเป็นห้องเดียว
- รูปทรงสร้างจากกรอบแนวแกนภาพ ยังไม่ใช่การจำลองผนังเอียง/โค้งอย่างแม่นยำ
- การกรองวัตถุซ้ำไม่รับประกันแก้ทุกกรณี และกรอบซ้อนที่ผิดคลาสยังต้องตรวจทาน
- ระบบไม่ทราบเองว่าห้องใดเป็นห้องนอน ห้องครัว หรือห้องน้ำ
- Undo/Redo เป็นประวัติการแก้ไขระหว่างใช้งาน ไม่ใช่ระบบประวัติเวอร์ชันบนเซิร์ฟเวอร์

หากจะเทรนบน Kaggle ต่อ ให้แยกปัญหาการตรวจจับออกจากปัญหา UI/เรขาคณิตก่อน เก็บภาพต้นฉบับ ผลผิด และผลที่คนแก้ถูก พร้อมแปลนหลายรูปแบบ การต้องการรูปทรงห้องโดยตรงอาจต้องเพิ่ม annotation แบบ mask/polygon และปรับการอ่านผลใน backend/frontend ด้วย ไม่ใช่เปลี่ยน `best.pt` แล้วคาดว่าแอปจะรองรับชนิดผลลัพธ์ใหม่ทันที

## 7. การทดสอบก่อนส่งต่องาน

ตรวจโค้ดและเรขาคณิตจากโฟลเดอร์หลัก:

```bash
npm run check
node tests/rooms.cjs
node tests/floor-plan-repair.cjs
```

ทดสอบผ่าน Chrome โดยเปิด frontend/backend ก่อน ติดตั้ง dependency ทดสอบครั้งแรก:

```bash
backend/.venv/bin/python -m pip install -r backend/requirements-test.txt
```

สคริปต์เบราว์เซอร์ใช้ Google Chrome ที่ติดตั้งในเครื่อง และโปรไฟล์ทดสอบแยก:

```bash
backend/.venv/bin/python backend/test_rooms.py
backend/.venv/bin/python backend/test_surfaces.py
backend/.venv/bin/python backend/test_wall_paint_ux.py
backend/.venv/bin/python backend/test_3d_interactions.py
backend/.venv/bin/python backend/test_browser_workflow.py /path/to/floor-plan.jpg
```

คำสั่งสุดท้ายต้องแทนพาธด้วยภาพแปลนจริงที่โมเดลตรวจพบวัตถุได้ ไม่ได้แถมพาธภาพส่วนตัวของผู้พัฒนาไปกับโปรเจกต์ ภาพผลทดสอบบันทึกใน `backend/test_results/`

ก่อนทำเอกสารนี้ การแก้เมนูผนังล่าสุดผ่าน lint/TypeScript/build และชุดทดสอบห้อง ผิวผนัง เมนูผนังใหม่ และ workflow อัปโหลดจริงแล้ว การแก้ฟังก์ชันครั้งถัดไปควรรันทดสอบส่วนที่เกี่ยวข้องใหม่

## 8. ส่งให้เพื่อนหรือเก็บบน GitHub

ส่งโค้ด `app/`, `components/`, `lib/`, `public/`, backend, ไฟล์ตั้งค่า, `package.json`, `package-lock.json`, requirements, tests และ docs ให้ครบ หากแยกส่งโมเดล ต้องนำไฟล์เดิมกลับมาวางที่ `backend/best.pt`

ไม่ต้องส่ง `node_modules/`, `.next/`, `backend/.venv/`, Python cache หรือไฟล์ผลทดสอบชั่วคราว เครื่องใหม่ต้องติดตั้ง dependency และสร้าง virtual environment ของตัวเอง ตรวจ `.gitignore` ก่อนเพิ่มไฟล์เข้า Git และใช้ `.env.example` เป็นตัวอย่างการตั้งค่าแทนไฟล์ค่าลับ

หากต้องการให้เพื่อนเปิดแปลนงานเดียวกัน ให้ส่ง `.sketch2spec.json` แยกจากโค้ดด้วย การมีไฟล์ในโฟลเดอร์ไม่ได้หมายความว่า commit หรืออัปขึ้น GitHub แล้ว ต้องดำเนินการ Git แยกต่างหาก
